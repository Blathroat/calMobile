# calMobile 移动端灰盒 UI 规范

## 1. 适用范围

本规范用于 `index.html` 与 `remaining-ui.html` 的移动端流程线框。当前板面覆盖 01–17 屏，内容按普通用户、展商和管理员分组。`index.html` 是 01–04 的基线来源，`remaining-ui.html` 是完整流程板。

## 2. 视觉基线

- 画布使用浅灰点阵背景，手机屏幕使用白色，手机边框使用深石墨色。
- 结构块使用浅灰填充和中灰描边，流程连接线、步骤标签和提示便签只使用橙色强调。
- 手机框维持约 `216 × 480px` 的线框比例，板面横向排列，流程通过虚线箭头和编号阅读。
- 界面保持低保真灰盒，不添加与业务无关的装饰、渐变或成品化插画。

## 3. 色彩 Token

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#f7f6f3` | 板面背景 |
| `--screen` | `#ffffff` | 手机屏幕与按钮底色 |
| `--ink` | `#20252b` | 主要文字 |
| `--ink-2` | `#626a74` | 次要文字与标签 |
| `--ink-3` | `#969da7` | 占位文字、辅助说明、弱化状态 |
| `--f3` | `#f1f2f4` | 输入框与结构块填充 |
| `--stroke` | `#c5cad1` | 结构描边 |
| `--accent` | `#c05621` | 流程步骤、焦点和提示 |
| `--dark` | `#48515d` | 主按钮与选中状态 |

不要在组件中重新发明颜色；新增规则优先引用已有 Token。

## 4. 表单规则

- 每个字段保留可见标签，不能只依赖占位文字。
- 标签和内容保持原有左右阅读方向，不做整组左右居中。
- 输入框内的文字使用 `display:flex` 与 `align-items:center` 实现上下居中；横向起点保持原有内边距。
- 05、11、17 的灰盒字段内容使用 `var(--ink-3)`，与 01 的 `wire-input::placeholder` 视觉一致。
- 真实输入控件使用 `.wire-input`；灰盒示意字段使用 `.input`，两者都保持浅灰填充、细描边和紧凑高度。
- 中文字段、占位文本和按钮标签使用短句，避免在手机框内产生不必要换行。

## 5. 按钮与操作位置

- 主要按钮使用深色实心样式，次要按钮使用白底描边样式。
- 单一底部操作放在屏幕右下角，使用圆形动作按钮；按钮必须保留可见焦点和 `aria-label`。
- 16 使用导出图标，17 使用保存图标；11、12 继续使用保存语义。
- 同一屏有两个并列决策时保留横向按钮组，例如 04 的“修改报名 / 撤销报名”或 13 的“拒绝 / 通过”。
- 触控区域不因图标缩小而缩小，圆形按钮保留至少 36px 的视觉尺寸，并通过外层节奏留出安全间距。
- 白底描边按钮（`.cta.ghost`）悬浮时填充 `--accent`，文字和描边切换为 `--screen`；深色实心按钮悬浮时保持深色层级。
- 分段控件中，未选中项悬浮时使用橙色填充；已选中的“需审核”等深色项悬浮时继续保持 `--dark`，避免状态反转。

## 6. 图标与状态

- 图标使用统一细线 SVG，约 12px，描边约 1.25；功能图标不使用 emoji。
- 颜色不是唯一状态线索：状态同时使用文字标签、描边或填充变化。
- 顶部返回、搜索和分享只保留中央细线图标，不显示圆框或底色；保留透明触控区域和可见焦点环。底部导航使用图标加文字。
- 连接箭头使用虚线，步骤标签使用单一编号和动词短语。

## 8. 编辑约束

- 修改优先作用于共享 Token 或组件规则，避免在单个屏幕写重复样式。
- `index.html` 的 01–04 基线内容只在用户明确要求时改动；同步到 `remaining-ui.html` 时保留屏幕文案、状态和流程语义。
- `data-od-id` 用于定位屏幕、连接器和说明便签；新增屏幕必须使用唯一 ID。
- `remaining-ui.html` 是可滚动的流程板，不要把多个手机屏幕叠放在同一坐标。
- 新增组件需要同时说明默认状态、选中状态和主要操作，避免只画静态装饰。
